# S3與資料生命週期

S3 是物件儲存。應用透過 API 上傳/讀取 `bucket + key`，不能把它當可任意更新區塊的 EBS。靜態檔案可由 CloudFront 讀 S3 origin，使用 OAC 保持 origin 私有；見 [[DNS與全球流量]]。

| 要求 | 候選能力 | 應確認 |
|---|---|---|
| 頻繁存取 | S3 Standard | 跨 AZ 設計、請求與傳輸費用 |
| 頻率不確定 | Intelligent-Tiering | 監控/自動分層條件與費用 |
| 少用但要快速讀 | Standard-IA | 最低儲存期間與取回費 |
| 可接受單 AZ 儲存風險 | One Zone-IA | 不適合作為唯一關鍵副本 |
| 長期封存 | Glacier 類別 | 恢復時間、最短儲存期間、取回費依類別不同 |

# 🧠 技術層
*它實際上怎麼運作——心智模型、機制、限制。**第一輪只讀這一層**，先把架構直覺建立起來。*

## 物件從建立到刪除

`PUT → (versioning) → lifecycle transition/expiration → 可選 replication → restore/delete`。Lifecycle 是同 bucket 內物件類別與過期規則；Replication 是來源與目標 bucket 之間複寫，通常需啟用版本控制，並區分同 Region/跨 Region。Versioning 保護誤覆寫/刪除的恢復能力，但會增加保留版本成本，不等於自動跨 Region 複本。

Presigned URL 讓持有人在期限與授權範圍內上傳/下載指定物件；簽發者須有對應權限。SSE-S3 與 SSE-KMS 的權限/審計差異要讀題目；若 private EC2 存取，串聯 [[EC2與網路]] 的 gateway endpoint 與 [[EC2與IAM安全]] 的授權。

案例：保單影像要多人讀、跨應用分享 → S3 object；需要多人對同一 Linux 目錄做 POSIX 檔案操作 → EFS。參見 [[EC2與儲存]]。


## 儲存類別的硬性條件

原表提醒了「有最低儲存期間與取回費」，這裡補上實際門檻——考題的成本計算常卡在這裡。

| 類別 | 最低儲存期間 | 取回費 | AZ 數 | 取回時間 |
|---|---:|:-:|:-:|---|
| **Standard** | 無 | 無 | ≥3 | 立即 |
| **Intelligent-Tiering** | 無 | **無** | ≥3 | 立即（Archive 層除外） |
| **Standard-IA** | **30 天** | 有 | ≥3 | 立即 |
| **One Zone-IA** | **30 天** | 有 | **1** | 立即 |
| **Glacier Instant Retrieval** | **90 天** | 有 | ≥3 | **毫秒** |
| **Glacier Flexible Retrieval** | **90 天** | 有 | ≥3 | 分鐘 ~ 數小時 |
| **Glacier Deep Archive** | **180 天** | 有 | ≥3 | **數小時（最長約 12–48 小時）** |

> [!danger] 兩個成本陷阱
> **(1) 提前刪除仍要付滿最低期間的費用。** 題目說「資料只保留 45 天」卻選 Glacier Flexible（最低 90 天）→ 反而更貴。
> **(2) 存取頻率不確定時，Intelligent-Tiering 是唯一沒有取回費的分層方案。**
> 題幹出現 `unpredictable access patterns`、`unknown or changing access` → **Intelligent-Tiering**，不要選 Standard-IA（猜錯會被取回費咬）。

> [!tip] Glacier 三兄弟的判斷句
> `archive but need milliseconds access` → **Instant Retrieval**
> `archive, retrieval within hours is acceptable` → **Flexible Retrieval**
> `lowest cost, 7-10 年法規保存, 極少取回` → **Deep Archive**

## Lifecycle 的方向限制

Lifecycle 轉換**只能往更冷的方向走**（Standard → IA → Glacier → Deep Archive），不能反向自動升溫；要取回冷資料必須 **restore**（產生暫時副本）。另外，**小於 128 KB 的物件轉到 IA 類別通常不划算**（可能反而更貴），Lifecycle 規則預設也不會轉換過小的物件。

## 上傳與傳輸

| 機制 | 用途 | 題幹關鍵字 |
|---|---|---|
| **Multipart Upload** | 大檔分段平行上傳、可續傳 | `large files`、`upload failures`、**>100 MB 建議、>5 GB 強制** |
| **Transfer Acceleration** | 經 CloudFront edge 加速長距離上傳 | `users worldwide upload to a single bucket`、`slow uploads from distant regions` |
| **Presigned URL** | 臨時授權單一物件的上傳/下載 | `allow a user to upload without AWS credentials` |
| **S3 Batch Operations** | 對數十億物件批次執行動作（複製、加標籤、還原） | `apply an operation to all existing objects` |

> [!warning] 未完成的 multipart upload 會持續計費
> 這是成本題的隱藏考點：中斷的分段上傳會留下已上傳的片段並持續收費。
> 正解：**設定 Lifecycle 規則自動清除未完成的 multipart upload**（`AbortIncompleteMultipartUpload`）。

## 資料保護

| 功能 | 作用 | 題幹關鍵字 |
|---|---|---|
| **Versioning** | 保留每個版本，刪除只放 delete marker | `accidental deletion`、`recover previous version` |
| **MFA Delete** | 刪除版本或關閉 versioning 需要 MFA | `prevent accidental permanent deletion` |
| **Object Lock** | **WORM 不可變**。**Governance mode** 特權使用者可繞過；**Compliance mode** **任何人（含 root）都不能刪改** | `immutable`、`WORM`、`regulatory retention`、`ransomware` |
| **Legal Hold** | 無到期日的保護，獨立於保留期 | `indefinite hold for litigation` |
| **Replication (SRR / CRR)** | 同 Region / 跨 Region 複寫，**需開啟 versioning** | CRR → `compliance in another region`、`lower latency for another region` |

> [!important] Object Lock 的三個前提
> **(1) 必須在建立 bucket 時啟用**（或透過支援請求對既有 bucket 啟用）。
> **(2) 必須同時啟用 versioning。**
> **(3) Compliance mode 一旦設定，保留期內連 root 帳號都無法刪除或縮短。** 題目強調 `even the root user cannot delete` → **Compliance mode**。

> [!note] Replication 的兩個限制
> 預設**只複寫啟用後的新物件**；要複寫既有物件需搭配 **S3 Batch Replication**。
> 複寫**不是備份**——來源端的刪除若設定為複寫 delete marker，目的地也會跟著看不到物件。真正的防刪除保護要靠 **versioning + Object Lock**。

## 存取控制與進階功能

| 功能 | 用途 |
|---|---|
| **Block Public Access** | 帳號/bucket 層級的總開關，**優先於**任何 bucket policy 或 ACL。排錯題：「policy 明明允許公開卻還是 403」→ 檢查這個 |
| **Bucket policy vs IAM policy** | 前者是資源政策（可跨帳號、可 `Principal: *`），後者綁在身分上。跨帳號存取需兩邊配合 |
| **S3 Access Points** | 為不同應用建立各自的存取端點與政策，取代一個龐大的 bucket policy |
| **Object Lambda Access Point** | 讀取時即時轉換物件（遮蔽 PII、改格式） |
| **Requester Pays** | 由下載方負擔傳輸費。題幹關鍵字 `share large datasets without paying egress` |
| **Storage Lens** | 跨帳號的儲存用量與最佳化建議 |
| **Event Notifications** | 物件事件觸發 **SNS / SQS / Lambda / EventBridge**。題幹關鍵字 `process images after upload` |
| **Mountpoint for Amazon S3** | 以檔案系統介面掛載 S3（唯讀為主的大資料場景）。注意**這不等於 POSIX 完整語意**，共享檔案系統仍選 EFS |

> [!tip] 事件驅動的標準組合
> 「使用者上傳圖片後要自動產生縮圖」→ **S3 Event Notification → Lambda**。
> 若下游處理較慢或需要重試緩衝 → **S3 → SQS → Lambda/worker**，見 [[事件驅動與無伺服器]]。

# 🎯 考試層
*考試會怎麼問——關鍵字反射、誘答陷阱、閉卷檢核。**第二輪與考前讀這一層**。*

## 🎯 考點速記

看到 `unpredictable access patterns` → **Intelligent-Tiering**（唯一沒有取回費）
看到保留天數 → 立刻對照**最低儲存期間**（30 / 90 / 180 天）
看到 `immutable` / `cannot be deleted even by root` → **Object Lock Compliance mode**
看到 `policy 允許公開但仍 403` → **Block Public Access**
看到 `slow uploads from distant regions` → **Transfer Acceleration**（不是 CloudFront）
看到 `upload failures on large files` → **multipart upload**
看到 `bill rising but no new data` → **未完成的 multipart upload**
看到 `keep S3 bucket private behind CloudFront` → **OAC**
看到 `temporary access to one object` → **presigned URL**

## 💣 真實場景陷阱

- **Replication 不是備份**：來源刪除若複寫 delete marker，目的地也會看不到物件。防刪除要靠 **versioning + Object Lock**。
- **Replication 預設不複寫既有物件**，只複寫啟用後的新物件；既有物件要用 **S3 Batch Replication**。
- **Versioning 一旦啟用只能暫停不能關閉**，而且舊版本會持續計費——沒設 lifecycle 清理舊版本是常見的帳單黑洞。
- **Lifecycle 只能往更冷的方向轉換**，不能自動升溫；小於 128 KB 的物件轉 IA 通常不划算。
- **SSE-KMS 的 KMS 請求配額**：大量小物件存取可能觸發限流，用 **S3 Bucket Keys** 大幅減少 KMS 呼叫。

## ✍️ 自我檢核

1. 資料保留 45 天、期間不存取、要最便宜——可以選 Glacier Flexible 嗎？為什麼？
2. bucket policy 明明允許公開卻還是 403，第一個該檢查什麼？實務上正確的架構是什麼？
3. Object Lock 的兩種模式差在哪？啟用它有哪兩個前提？
4. 「帳單持續上升但團隊說沒新增資料」——最可能的原因與解法？
5. Transfer Acceleration 與 CloudFront 各加速什麼方向？

> [!success]- 參考答案
> 1. **不行**。Glacier Flexible 最低儲存期間 **90 天**，只放 45 天仍要付滿 90 天——反而更貴。正解是 Standard-IA 或 One Zone-IA（最低 30 天）。
> 2. **S3 Block Public Access**（優先序高於任何 bucket policy 與 ACL）。但實務上不該為了靜態網站關閉它，正解架構是 **CloudFront + OAC 保持 bucket 私有**。
> 3. **Governance mode 特權使用者可繞過；Compliance mode 連 root 都不能刪改。** 前提：**建立 bucket 時啟用**（或透過支援請求）+ **必須同時啟用 versioning**。
> 4. **未完成的 multipart upload** 留下的片段持續計費，且在物件清單中看不到。解法是 Lifecycle 規則 **`AbortIncompleteMultipartUpload`**。
> 5. **Transfer Acceleration 加速「上傳」到 S3**（經 edge 走 AWS 骨幹）；**CloudFront 加速「下載」**（快取）。題目說上傳慢而選 CloudFront 是錯的。
