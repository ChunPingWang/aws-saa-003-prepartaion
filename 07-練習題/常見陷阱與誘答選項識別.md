# 常見陷阱與誘答選項識別

> [!danger] 這篇可能直接值 5–10 分
> 專業級考試的錯誤選項**不是隨便亂寫的**，它們針對特定的認知盲點設計。
> **認出誘答的套路，比多背一個服務有效。**

---

# 🔑 Part 1：關鍵限制詞 → 直接砍一半選項

題幹裡的每個形容詞都是篩選器。看到左欄，立刻執行右邊兩欄。

| 題目出現 | 選 | 砍掉 |
|---|---|---|
| `least operational overhead`、`fully managed`、`no servers to manage` | Lambda、Fargate、Aurora Serverless、DynamoDB、S3、託管服務 | 自建、EC2、**EKS**、自寫排程腳本 |
| `minimal code changes`、`without rewriting the application`、`lift and shift` | EC2、**Amazon MQ**、**EFS/FSx**、RDS | 改成 serverless、改用 S3 物件 API、改用 SQS |
| `most cost-effective` | **先用其他條件淘汰，剩下的才比價** | 忽略硬性條件的最低價選項 |
| `highly available` | 多 AZ、Multi-AZ、ASG 跨 AZ | 跨 Region 方案（**沒說 Region 就別選**） |
| `disaster recovery`、`region failure` | 跨 Region 複寫、Global Database、Route 53/GA 切換 | Multi-AZ（**只跨 AZ**） |
| `without traversing the public internet` | VPC endpoint、PrivateLink、Direct Connect | NAT gateway、公有子網 |
| `decouple` | SQS、SNS、EventBridge | 同步 API 呼叫 |
| `real-time`、`sub-second` | Kinesis Data Streams、ElastiCache、DAX | Firehose、Athena |
| `near real-time`（分鐘級） | **Data Firehose** | Data Streams |
| `unpredictable`、`spiky`、`intermittent` | On-Demand、DynamoDB on-demand、Aurora Serverless v2、Intelligent-Tiering | RI、Provisioned 固定容量、Standard-IA |
| `steady state`、`1 or 3 year commitment` | Savings Plans / RI | On-Demand、Spot |
| `fault-tolerant`、`can be interrupted`、`flexible start time` | **Spot** | On-Demand |
| `POSIX`、`shared file system`、`NFS`、`mount` | **EFS**（Linux）/ **FSx**（Windows） | **S3（不是 POSIX）** |
| `Windows`、`SMB`、`Active Directory` | **FSx for Windows** | EFS |
| `HPC`、`machine learning training` | **FSx for Lustre** | EFS |
| `order must be preserved`、`no duplicates` | **SQS FIFO** | Standard |
| `multiple consumers process the same data`、`replay` | **Kinesis Data Streams** | SQS、SNS |
| `existing JMS / AMQP` | **Amazon MQ** | SQS |
| `existing Kafka` | **MSK** | Kinesis |
| `who called which API`、`audit trail` | **CloudTrail** | CloudWatch、Config |
| `configuration compliance`、`drift`、`ensure all X are encrypted` | **AWS Config** | CloudTrail |
| `alert when spending exceeds` | **AWS Budgets** | Cost Explorer |
| `immutable`、`cannot be deleted even by root`、`ransomware` | **Object Lock / Vault Lock（Compliance mode）** | Versioning、MFA Delete、跨帳號複製 |
| `automatic rotation` | **Secrets Manager** | Parameter Store |
| `without opening inbound ports`、`no bastion` | **Session Manager** | bastion host、VPN |
| `FIPS 140-3 Level 3`、`single-tenant HSM` | **CloudHSM** | KMS（含 BYOK） |
| `millions of app users sign in` | **Cognito** | **IAM user（永遠是錯的）** |
| `employees access multiple AWS accounts` | **IAM Identity Center** | Cognito、每帳號建 IAM user |
| `eliminate cold start` | **Provisioned concurrency** | reserved concurrency |
| `too many connections` from Lambda | **RDS Proxy** | 加大 DB instance |
| `data residency`、`must be served from <region>` | **Geolocation routing** | Latency-based |
| `static IP for firewall allowlist` | **NLB** 或 **Global Accelerator** | ALB（沒有靜態 IP） |
| `petabytes` + `limited bandwidth` | **Snow Family** | 網路傳輸 |
| `limited bandwidth` 但**算一下網路傳得完** | **DataSync** | Snowball（過度設計） |

# 🎭 Part 2：八種誘答套路

## 套路 ①「服務根本不支援」

最容易砍掉的錯誤選項。看到就直接刪。

| 誘答 | 為什麼不可能 |
|---|---|
| 把 **WAF 附加到 NLB** | WAF 只支援 CloudFront / ALB / API Gateway / AppSync / Cognito UP / App Runner / Verified Access |
| **Gateway endpoint** 用於 S3、DynamoDB **以外**的服務 | 只有這兩個 |
| **NAT Gateway** 處理 IPv6 | NAT 只做 IPv4；IPv6 要 egress-only IGW |
| **VPC Peering 遞移路由** | 不支援，要 TGW |
| **CNAME 用在 zone apex** | DNS 標準禁止，只能用 Alias |
| CloudFront 使用**非 us-east-1** 的 ACM 憑證 | 必須簽發在 us-east-1 |
| **DynamoDB read replica** | DynamoDB 沒有這個概念（是 Global Tables） |
| **Multi-AZ standby 拿來分攤讀取** | DB *instance* 的 standby 不可讀（DB *cluster* 才有 reader） |
| **EBS Multi-Attach 跨 AZ** 或掛一般 ext4/XFS | 僅同 AZ、僅 io1/io2、需 cluster-aware FS |
| **st1 / sc1 當開機碟** | HDD 類型不能開機 |
| **就地為既有 RDS/EBS 啟用加密** | 必須 snapshot → 加密複製 → 還原 |
| **Lambda 執行超過 15 分鐘** | 硬上限 |
| **SCP 授予權限** | SCP 只設上限，永遠不授權 |
| **SCP 限制管理帳號** | 對 management account 無效 |
| **Athena 建索引 / 換更大 instance** | 無伺服器，沒有 instance 也沒有索引 |
| **Fargate 使用 GPU** | 不支援 |
| 縮短已鎖定的 **Object Lock Compliance** 保留期 | 不可逆，連 root 都不行 |

## 套路 ②「權限過大 / 憑證外洩」

只要選項出現下列任一，幾乎可以直接砍：

- 把 **access key 放進** 程式碼、環境變數、AMI、user data、設定檔
- 為**終端使用者**建立 IAM user 並發放金鑰
- 附加 `AdministratorAccess` 或 `*:*` 來「解決」權限問題
- 把 S3 bucket **設為公開**來讓 CloudFront 或某服務讀取（正解是 **OAC**）
- 給 **EC2 節點** role 而不是給 **Pod/Task** role（違反最小權限）

> [!tip] 正解永遠是
> EC2/ECS/Lambda → **IAM role**；地端 → **IAM Roles Anywhere**；員工 → **IAM Identity Center**；App 使用者 → **Cognito**。

## 套路 ③「網路方案解權限問題」（或反過來）

| 症狀 | 正確方向 | 誘答 |
|---|---|---|
| `AccessDenied` / 403 | IAM → 資源 policy → endpoint policy → SCP → **KMS** | 「移到公有子網」「開 NACL」「改用 interface endpoint」 |
| Timeout / 無回應 | DNS → route → SG → NACL → 目標服務 | 「加 IAM 權限」「改 bucket policy」 |

**Timeout 找網路，403 找權限。** 這一條在考場能省下大量時間。

## 套路 ④「過度設計」

技術上可行，但超出題目需求——**題幹有 `cost-effective` 或 `simplest` 時必錯**。

| 需求 | 過度設計的誘答 | 正解 |
|---|---|---|
| AZ 故障容錯 | 跨 Region active-active | Multi-AZ |
| RTO 4 小時 | Multi-site active/active | Pilot light |
| 沒提到順序 | FIFO queue | Standard queue |
| 沒提到 Kubernetes | EKS | ECS on Fargate |
| 10 TB + 1 Gbps 專線 | Snowball | DataSync |
| 存放組態、成本最低 | Secrets Manager | Parameter Store |
| 一般加密需求 | CloudHSM | KMS |

## 套路 ⑤「維運負擔高的土炮解法」

出現 `least operational overhead` 時必錯，但**沒有這個限制時可能是對的**——要看題幹。

- 「寫 Lambda 定期分析存取紀錄並搬移 S3 儲存類別」→ 應該用 **Intelligent-Tiering**
- 「為每個服務各寫 snapshot 排程腳本」→ 應該用 **AWS Backup**
- 「在 EC2 上自建 cron 排程」→ 應該用 **EventBridge Scheduler**
- 「手動在下班後停止 RDS」→ 應該用 **Aurora Serverless v2**
- 「自行在兩個 Region 同步 DynamoDB 表」→ 應該用 **Global Tables**

## 套路 ⑥「名詞張冠李戴」

把 A 服務的術語套到 B 服務上。**這類選項通常寫得很順、很像真的。**

| 假名詞 | 真相 |
|---|---|
| DynamoDB 的 read replica | 是 **Global Tables** |
| S3 的 Multi-AZ 設定 | S3 本來就跨 AZ，沒有這個開關 |
| Lambda 的 Auto Scaling group | Lambda 自動擴展，沒有 ASG |
| EFS 的 Multi-Attach | 是 EBS 的功能 |
| Aurora 的 instance store | Aurora 是叢集儲存 |
| CloudFront 的 target group | 是 ELB 的概念 |

## 套路 ⑦「只解決一半」

選項處理了症狀但沒處理根因，或只滿足題幹的部分條件。

| 題目 | 只解決一半 | 完整解 |
|---|---|---|
| 訊息重複處理 | 改用 FIFO | **調長 visibility timeout**（並保持冪等） |
| 使用者擴縮後被登出 | sticky session | **session 外部化到 ElastiCache/DynamoDB** |
| 應用當掉但 ASG 不替換 | 縮短 ALB 健康檢查間隔 | **ASG health check type 改為 ELB** |
| DynamoDB 限流但容量有剩 | 加容量 | **重新設計 partition key** |
| 帳單上升、有中斷的大檔上傳 | 啟用 Storage Lens（只能發現） | **Lifecycle 清除未完成 multipart upload** |

## 套路 ⑧「數字陷阱」

用一個具體數字讓看似合理的選項出局。**讀到數字要立刻對照門檻。**

| 題幹數字 | 觸發的門檻 |
|---|---|
| 執行 20 / 40 分鐘 | **Lambda 15 分鐘上限** |
| 保留 45 天 | **Glacier Flexible 最低 90 天、Deep Archive 180 天** |
| 處理耗時 90 秒 | **SQS visibility timeout 預設 30 秒** |
| 上傳 8 GB 單檔 | **單次 PUT 上限 5 GB → multipart** |
| 訊息 1 MB | **SQS 上限 256 KB → S3 + Extended Client** |
| item 500 KB | **DynamoDB item 上限 400 KB** |
| RPO 1 秒 / RTO 1 分鐘 | **Aurora Global Database** |
| 每 AZ 8 台關鍵實例 | **Spread placement group 每 AZ 上限 7 台** |
| `/24` 需要 256 個 IP | **AWS 保留 5 個，只剩 251** |

# 🧠 Part 3：讀題的四個動作

> [!important] 順序很重要
> **1. 先讀最後一句問句** — 知道它到底在問什麼（選一個？選兩個？問「最」什麼？）
> **2. 再讀所有選項** — 建立比較維度，知道題目想區分什麼
> **3. 回頭掃題幹圈出限制詞** — 每一個形容詞都是篩選器
> **4. 逐一淘汰，說出每個選項死在哪個條件**

不要從題幹第一個字逐行讀。10 行以上的長題幹通常限制條件明確、**反而好排除**；真正吃時間的是短題幹但四個選項都很像的題目。

## 複選題（choose TWO / THREE）的做法

- **先找出最確定的那一個**，再用它的邏輯去篩其他。
- 兩個正解通常是**互補**的（一個處理網路、一個處理權限；一個處理運算、一個處理資料），而不是同一個層面的兩種做法。
- 題目說 choose TWO 就**一定要選滿兩個**——少選等於錯。

## 最後檢查

- 我選的方案**滿足題幹的每一個條件**嗎？（逐條對照，不是憑感覺）
- 有沒有**更簡單/更便宜**且同樣滿足的選項？
- 我排除的三個，能各說出**死在哪個具體條件**嗎？說不出來代表我可能在猜。

## ✍️ 自我檢核

1. 看到 `least operational overhead`，哪三類選項要立刻砍掉？
2. 題幹說「RTO 4 小時、成本最低」，為什麼 active/active 是錯的？
3. `AccessDenied` 時你**不會**檢查什麼？
4. 「訊息被重複處理」的完整解與「只解決一半」的解各是什麼？
5. 選項寫「為 DynamoDB 建立跨 Region read replica」——這句話哪裡有問題？

<details>
<summary>參考答案</summary>

1. **自建/土炮腳本**、**EC2 與 EKS**（相對於 Fargate/Lambda）、**需要人工介入的定期作業**。
2. 這是**過度設計**。RTO 4 小時很寬鬆，pilot light 就能達標且常駐成本低得多。DR 題永遠是「**在滿足 RTO/RPO 的前提下選最便宜的**」。
3. **不會檢查 route table、NACL、子網位置**——那些是網路問題，症狀會是 **timeout** 不是 403。要查的是 IAM → 資源 policy → endpoint policy → SCP → KMS。
4. 完整解是**調長 visibility timeout 到大於處理時間**（根因）；只解決一半的是**改用 FIFO**（提供去重但沒解決 timeout 太短，且犧牲吞吐、題目也沒要求順序）。兩者之外，**consumer 冪等**是設計責任。
5. **DynamoDB 沒有 read replica 這個概念**——這是把 RDS 的術語套到 DynamoDB 上（套路 ⑥）。多 Region 是 **Global Tables**。

</details>
