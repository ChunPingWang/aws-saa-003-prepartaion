# 模考與錯題模板

## 每題複盤

```markdown
### 題號／日期
- Domain：安全／韌性／效能／成本
- 題目關鍵需求：
- 必要條件（RPO、RTO、延遲、費用、維運）：
- 我的答案／正解：
- 正解成立的原因：
- 其他選項不合需求的原因：
- 混淆的 AWS 細節與官方來源：
- 三天後重做結果：
```

## 模考紀錄

正式考試為 **65 題 / 130 分鐘**，模考請照這個規格計時（詳見 [[00 考試總覽]]）。

| 日期 | 題數 | 限時 | 正確率 | 未完成 | 最弱兩類 | 行動 |

| Day 20 | 65 | 130 分鐘 |  |  |  |  |
| Day 23 | 65 | 130 分鐘 |  |  |  |  |
| Day 24 | 65 | 130 分鐘 |  |  |  |  |

優先修正「同類型反覆錯」與「答對但理由錯」。Day 25 只重看弱點與 [[選型比較與常見陷阱]]，不要只背關鍵字：`high availability` 必須確認故障邊界；`minimum operational overhead` 也不能忽略硬性相容條件。正式考試題數/時間及通過規則以 [[03 官方資源清單]] 即時資訊為準。

## 依 domain 追蹤弱點

官方權重：**安全 30%｜韌性 26%｜效能 24%｜成本 20%**。補償式計分只看總分，但錯題集中在某個 domain 就代表該區塊的理解有系統性缺口。

| Domain | 權重 | 模考 #1 | #2 | #3 | 對應筆記 |
|---|---:|---:|---:|---:|---|
| 安全 | 30% |  |  |  | [[EC2與IAM安全]]、[[身分聯合與應用存取]]、[[威脅偵測與邊界防護]]、[[治理與合規]] |
| 韌性 | 26% |  |  |  | [[高可用備援與災難復原]]、[[事件驅動與無伺服器]]、[[EC2與負載平衡及擴展]] |
| 效能 | 24% |  |  |  | [[EC2與儲存]]、[[資料庫與快取]]、[[資料分析與串流]]、[[運算與容器選型]] |
| 成本 | 20% |  |  |  | [[成本與可觀測性]]、[[運算與容器選型]]、[[S3與資料生命週期]] |

## 錯題分類

把每道錯題歸到下列其中一類，**類型比題目本身更值得記錄**：

| 類型 | 意思 | 修法 |
|---|---|---|
| **知識缺口** | 根本不知道這個服務/功能 | 讀對應筆記，補進 [[選型比較與常見陷阱]] |
| **選型混淆** | 兩個服務分不清楚 | 寫出「什麼條件下選 A 而非 B」，補進比較表 |
| **漏讀限制** | 題幹有條件被忽略（時間、成本、合規、不可改程式碼） | 練習**先讀問句與選項再回頭找限制條件** |
| **過度設計** | 選了技術上可行但超出需求的方案 | 重讀該題，問「最便宜/最簡單且滿足全部條件的是哪個」 |
| **數字卡關** | 因為不知道某個門檻而排除錯選項 | 記進 [[數字與門檻速查]] |
| **答對但理由錯** | 猜對或理由錯誤 | **等同錯題處理**，這類最危險 |

> [!tip] 三天後重做
> 每道錯題在三天後重做一次。若第二次仍錯或理由仍不完整，該主題就要回到原始筆記重讀，而不是只記答案。可搭配 [[情境題庫]] 的「變形題」自我檢驗：**改掉題幹的一個限制條件，答案會不會變？**
