# 實作路線

> [!warning] 費用
> AWS 免費方案依帳號及服務條件而異。NAT gateway、ALB、RDS、跨 AZ 流量、interface endpoint 可能持續計費；先查看價格、設 AWS Budgets 提醒，每個 Lab 完成即清除。若不準備實際付費，改畫架構、讀官方範例並做紙上封包追蹤。

## Lab A：private EC2 與三條網路路徑（Day 5–7）

1. 設計 2 AZ；每 AZ public/app private subnet；public route 到 IGW，private route 依方案到 NAT。
2. EC2 置 private subnet、無 public IP；用 Systems Manager Session Manager 管理時，先確認 agent、role 及對 SSM API 的網路路徑。不要假設建立 EC2 後立即可登入。
3. 畫出 EC2 到 Internet、S3 gateway endpoint、ALB 入站三條路；檢查 route table、SG/NACL、身份與 endpoint policy。
4. 故障演練：移除適當路由或 policy，在紙上預測 timeout 與 AccessDenied 差異。

## Lab B：EC2 與儲存（Day 3、8–9）

1. 在同 AZ 連接 EBS，觀察 volume 與 EC2 是否獨立存在；作 snapshot，畫恢復流程。
2. 比較另一個 AZ 如何取得資料：用 snapshot 建新 volume，或改用 EFS 的 mount targets / S3 API。
3. 對私有 S3 bucket 開版本控制、Lifecycle（先確認費用）、以 EC2 role 讀取；將授權與網路失敗分開排查。

## Lab C：應用擴縮與資料（Day 4、10、20）

1. 畫 ALB → target group → 跨 AZ ASG；檢查健康檢查及失敗替換。
2. 選一個 Spring Boot API，把 session、上傳檔及 DB 移出 instance；標出每層故障範圍。
3. 給定 RPO 15 分鐘、RTO 2 小時，提出 Region 故障恢復程序並列出待驗證假設；不要把 Multi-AZ 當跨 Region DR。

## Lab D：零入站端口的維運存取（Day 13–14，幾乎免費）

這個 Lab 對應高頻考點且成本極低，值得做。

1. 對 Lab A 的 private EC2 加上帶 `AmazonSSMManagedInstanceCore` 的 instance profile，用 **Systems Manager Session Manager** 連入——**全程不開任何入站端口、不需要 SSH key、不需要 bastion**。
2. 若連不上，依序檢查三件事：SSM Agent 是否執行、instance profile 是否正確、**到 SSM API 的網路路徑**（NAT gateway 或 `ssm` / `ssmmessages` / `ec2messages` 三個 interface endpoint）。這個排錯過程本身就是考題。
3. 在 **Parameter Store** 存一個 SecureString，用 EC2 的 role 讀取；再刻意移除 `kms:Decrypt` 權限，觀察錯誤訊息如何從成功變成 `AccessDenied`——體會「兩層授權」。
4. 對照 [[治理與合規]] 的 Parameter Store vs Secrets Manager 比較表，寫下你在什麼條件下會改用 Secrets Manager。

## 紙上 Lab：不花錢也能練的三題

若不打算實際開資源，這三個推演的訓練效果接近實作：

1. **成本推演**：畫出 Lab A 的架構，標出每一條線的計費點（NAT gateway 處理費、跨 AZ 流量、interface endpoint 時數）。然後回答：把 S3 存取改走 gateway endpoint 後，哪幾條線的費用歸零？對應 [[成本與可觀測性]]。
2. **故障推演**：在同一張圖上，依序假設「單台 EC2 死亡 → 整個 AZ 失效 → 整個 Region 失效」，每一層寫下需要哪個機制才能存活，以及 RPO/RTO 各是多少。對應 [[高可用備援與災難復原]]。
3. **權限推演**：追蹤一次「EC2 讀取 SSE-KMS 加密的 S3 物件」，列出必須同時成立的**五個**授權層（IAM identity policy、bucket policy、endpoint policy、SCP、KMS key policy），並各寫一個會導致 403 的設定錯誤。對應 [[EC2與IAM安全]]、[[威脅偵測與邊界防護]]。
