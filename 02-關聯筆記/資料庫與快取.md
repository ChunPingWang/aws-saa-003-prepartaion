# 資料庫與快取

`App private subnet → DB security group → RDS/Aurora`；依讀寫、交易模型、HA 與全球分布選型，而非單看「NoSQL 比 SQL 快」。

| 需求 | 候選 | 注意 |
|---|---|---|
| SQL、關聯與交易 | RDS / Aurora | engine、成本、兼容性 |
| 一般 RDS DB instance 的 AZ 故障自動切換 | Multi-AZ DB instance | standby 用於 HA，不供直接讀取 |
| 一般 DB instance 分攤讀取 | Read Replica | 複寫通常非同步，可能有 lag；不是同義於 HA 自動切換 |
| 讀取擴展兼 HA | Aurora replicas，或 RDS Multi-AZ DB cluster | Multi-AZ **DB cluster** 有可讀 reader，勿套用上述 instance 版敘述 |
| 大量 key-value、依 access pattern 查詢 | DynamoDB | partition key 與 GSI 設計、capacity mode |
| 熱資料快取 | ElastiCache / DynamoDB 專用 DAX | 快取失效、最終一致性/失效策略 |

Aurora 使用分離的叢集儲存和 DB instances；Aurora Global Database 處理跨 Region 讀取/災難情境，跨 Region 複寫仍應評估 lag 與故障切換流程。DynamoDB Global Tables 可做多 Region 複寫；強一致、交易與衝突語義要依題目限制。

**一個常見混淆**：「Multi-AZ 不能讀 standby」只對標準 RDS Multi-AZ DB *instance* 的 standby 說法成立；Multi-AZ DB *cluster* 有 reader DB instances。考試題幹的部署名詞要逐字辨識。

Spring Boot 案例：訂單狀態更新須 ACID → RDS/Aurora；查詢量飆升 → 讀 replica 或 cache，但也檢查讀寫一致性；工作解耦 → [[事件驅動與無伺服器]]。持久 DB 不靠 ASG 內的 EC2 本地檔案，見 [[EC2與負載平衡及擴展]]。
