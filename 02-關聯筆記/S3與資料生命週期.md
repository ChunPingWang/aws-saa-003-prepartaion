# S3與資料生命週期

S3 是物件儲存。應用透過 API 上傳/讀取 `bucket + key`，不能把它當可任意更新區塊的 EBS。靜態檔案可由 CloudFront 讀 S3 origin，使用 OAC 保持 origin 私有；見 [[DNS與全球流量]]。

| 要求 | 候選能力 | 應確認 |
|---|---|---|
| 頻繁存取 | S3 Standard | 跨 AZ 設計、請求與傳輸費用 |
| 頻率不確定 | Intelligent-Tiering | 監控/自動分層條件與費用 |
| 少用但要快速讀 | Standard-IA | 最低儲存期間與取回費 |
| 可接受單 AZ 儲存風險 | One Zone-IA | 不適合作為唯一關鍵副本 |
| 長期封存 | Glacier 類別 | 恢復時間、最短儲存期間、取回費依類別不同 |

## 物件從建立到刪除

`PUT → (versioning) → lifecycle transition/expiration → 可選 replication → restore/delete`。Lifecycle 是同 bucket 內物件類別與過期規則；Replication 是來源與目標 bucket 之間複寫，通常需啟用版本控制，並區分同 Region/跨 Region。Versioning 保護誤覆寫/刪除的恢復能力，但會增加保留版本成本，不等於自動跨 Region 複本。

Presigned URL 讓持有人在期限與授權範圍內上傳/下載指定物件；簽發者須有對應權限。SSE-S3 與 SSE-KMS 的權限/審計差異要讀題目；若 private EC2 存取，串聯 [[EC2與網路]] 的 gateway endpoint 與 [[EC2與IAM安全]] 的授權。

案例：保單影像要多人讀、跨應用分享 → S3 object；需要多人對同一 Linux 目錄做 POSIX 檔案操作 → EFS。參見 [[EC2與儲存]]。
