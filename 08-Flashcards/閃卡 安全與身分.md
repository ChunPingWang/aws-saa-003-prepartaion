## 🔐 IAM 與權限評估

IAM 權限評估的三條鐵律？::**① 預設拒絕（隱含）② 任何一層的 explicit Deny 直接否決 ③ 權限上限機制（SCP、permission boundary）只能限縮不能授予**

有效權限怎麼算？
?
**IAM policy ∩ SCP ∩ permission boundary ∩ resource policy**
任何一層出現 explicit Deny 就直接拒絕，沒有例外。

SCP 會授予權限嗎？::**不會**。它只設「權限天花板」，帳號內仍需 IAM policy 明確 Allow

SCP 對哪個帳號無效？::**管理帳號（management account）**——所以最佳實務是管理帳號不放工作負載

SCP 與 permission boundary 的作用範圍差別？::**SCP = 帳號/OU 的天花板**；**permission boundary = 單一身分的天花板**

「允許開發者自建 IAM role，但他們建的 role 權限不能超過某範圍」→ 用什麼？::**permission boundary**（SCP 粒度太粗，會一併限制整個帳號）

跨帳號 AssumeRole 需要幾邊設定？::**兩邊**——目標帳號的 role **trust policy** 要信任來源，來源帳號的 IAM policy 要允許 `sts:AssumeRole`

第三方廠商要 assume 你的 role，必須加什麼條件？為什麼？::**`sts:ExternalId`**——防止 **confused deputy（混淆代理人）**，避免廠商被誘導存取其他客戶資源

IAM role 的預設 session 有效期？::1 小時（可設 1–12 小時）

## 👤 三種「使用者」

App 的數百萬終端使用者要用 Google 登入 → 選什麼？::**Cognito**（絕對不是為每人建 IAM user）

Cognito User Pool 與 Identity Pool 的職責？
?
**User Pool = 認證（authN）**：使用者目錄、社群/SAML 聯合，回傳 **JWT**。
**Identity Pool = 授權（authZ）**：把 token 換成 **AWS 臨時憑證**，讓使用者直接存取 S3/DynamoDB；支援 guest 存取。

「手機 App 要直接上傳到 S3」需要 Cognito 的哪個元件？::**Identity Pool**（只有它能換到 AWS 憑證）

50 個帳號的員工要用既有 AD 登入 → 選什麼？::**IAM Identity Center**（permission set 指派到「使用者/群組 × 帳號」）

AD Connector 與 AWS Managed Microsoft AD 怎麼選？::要用**既有 on-prem AD 且 AWS 端不存目錄資料** → **AD Connector**；要在 AWS 有獨立完整 AD → **Managed Microsoft AD**

地端工作負載要免長期金鑰取得 AWS 憑證 → 用什麼？::**IAM Roles Anywhere**（X.509 憑證換臨時憑證）

哪些選項看到就可以直接砍？::把 **access key 放進程式碼 / 環境變數 / AMI / user data**；為終端使用者建 IAM user；附加 `AdministratorAccess` 解決權限問題

## 🛡 安全服務一句話

GuardDuty 做什麼？::**威脅行為偵測**——從 VPC Flow Logs、DNS logs、CloudTrail 偵測異常 API、挖礦、遭入侵的實例

Inspector 做什麼？::**漏洞掃描**——EC2、ECR 映像、Lambda 的 CVE 與網路可達性

Macie 做什麼？::在 **S3** 中**發現敏感資料（PII）**

Security Hub 做什麼？::**彙整**各安全服務的 findings + 合規標準計分（CIS、PCI、AWS FSBP）

Detective 做什麼？::對 findings 做**根因調查**與關聯分析

GuardDuty 與 Inspector 一句話分辨？::**GuardDuty 看「有沒有壞事正在發生」（行為）；Inspector 看「有沒有已知弱點」（漏洞）**

Macie 與 Inspector 一句話分辨？::**Macie 看資料內容（S3 裡有什麼）；Inspector 看運算資源（有沒有未修補 CVE）**

Shield Standard 要付費嗎？::**不用，免費且自動啟用**（L3/L4 DDoS）

Shield Advanced 多了什麼？::**DDoS Response Team（DRT）** 與**攻擊期間擴容的費用保護**

WAF、Network Firewall、Security Group 各在哪一層？::**WAF = L7 HTTP 規則**；**Network Firewall = VPC 層全協定 IDS/IPS**；**SG = ENI 層的端口與來源**

WAF 的 rate-based rule 用來擋什麼？::`brute force`、`HTTP flood`——限制單一 IP 在時間窗內的請求數

Firewall Manager 做什麼？::跨 Organizations **集中管理** WAF / Shield Advanced / SG / Network Firewall 規則

`FIPS 140-3 Level 3` + `single-tenant` + `AWS 不得存取金鑰` → 選什麼？::**CloudHSM**（KMS 是多租戶；即使 BYOK，金鑰仍存在 KMS 的多租戶 HSM）

## 🔑 KMS 與加密

KMS 金鑰刪除的等待期？::**7–30 天**（期間可取消）

KMS 可直接加密的資料大小上限？超過怎麼辦？::**4 KB**，更大要用 **envelope encryption**（data key 加密資料、CMK 加密 data key）

CMK 是 Region 專屬的嗎？這造成什麼考點？::**是**。跨 Region 複寫加密資料時必須處理目的地 Region 的金鑰——用 **multi-Region key** 或授予兩邊權限

AWS managed key 與 customer managed key 的差別？::AWS managed 免費但**無法自訂 key policy**；CMK 可寫 key policy、可啟用自動輪替、可停用刪除

沒有 key policy 允許，IAM 管理員能用這把金鑰嗎？::**不能**。key policy 是 KMS 的資源政策，必須明確允許

EC2 讀取 SSE-KMS 加密的 S3 物件需要哪兩層權限？::**`s3:GetObject`** 與對該 CMK 的 **`kms:Decrypt`**

S3 的五種加密選項？::SSE-S3、SSE-KMS、DSSE-KMS、SSE-C（你提供金鑰）、client-side

大量小物件存取 SSE-KMS 觸發 KMS 限流怎麼辦？::啟用 **S3 Bucket Keys**（大幅減少 KMS 呼叫）

CloudFront 的 ACM 憑證必須簽發在哪？::**us-east-1**

## 🏛 治理與稽核

CloudTrail、AWS Config、CloudWatch 各記錄什麼？
?
**CloudTrail 記錄「動作」**（誰呼叫了哪個 API）
**Config 記錄「狀態」**（資源設定是什麼、合規嗎、何時被改）
**CloudWatch 記錄「表現」**（指標、日誌、告警）

「稽核是誰刪了這個 bucket」→ 用什麼？::**CloudTrail**

「確保所有 EBS volume 都加密，違規自動修正」→ 用什麼？::**AWS Config 規則 + remediation action**（SSM Automation），跨帳號用 conformance pack

CloudTrail 的 data events 預設開啟嗎？::**預設關閉**且另外收費。要稽核 S3 物件層級存取必須啟用

CloudTrail 主控台能查多久的事件歷史？::**90 天**。更長要送 S3 或用 CloudTrail Lake

Systems Manager Session Manager 解決什麼？::**不開任何入站端口、不需 bastion、不需 SSH key** 就能連進 EC2，且工作階段可稽核

Session Manager 的三個前提？::**SSM Agent** + 帶 `AmazonSSMManagedInstanceCore` 的 **instance profile** + 到 SSM API 的**網路路徑**（NAT 或 `ssm`/`ssmmessages`/`ec2messages` endpoint）

Parameter Store 與 Secrets Manager 怎麼選？::看到 **`automatic rotation`** → **Secrets Manager**；只說「安全存放組態、成本最低」→ **Parameter Store（免費）**

「連 root 都不能刪除的備份」有哪兩種實作？::**S3 Object Lock（Compliance mode）** 與 **AWS Backup Vault Lock（合規模式）**

AWS Backup 相對「各服務自己排程 snapshot」的優勢？::**一套政策涵蓋多服務多帳號**，支援跨 Region / 跨帳號複製與 Vault Lock

Control Tower 的兩種 guardrail 各由什麼實作？::**preventive = SCP**；**detective = Config rule**

CloudFormation StackSets 解決什麼？::一次部署同一組資源到**多帳號多 Region**（與 Organizations 整合）

AWS RAM 做什麼？::跨帳號**共享資源**（VPC subnet、Transit Gateway、Route 53 Resolver rule）
