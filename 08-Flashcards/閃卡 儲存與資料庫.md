## 💾 區塊與檔案儲存

gp3 相對 gp2 的關鍵優勢？::**IOPS 與吞吐量可獨立於容量調整**（gp2 是 3 IOPS/GB 綁死），而且更便宜

「大型循序讀寫、成本敏感、非開機碟」選哪種 EBS？::**st1（吞吐量最佳化 HDD）**

哪些 EBS 類型不能當開機碟？::**st1 與 sc1**（HDD 類型）

EBS Multi-Attach 的三個限制？::**僅 io1/io2**、**同一 AZ**、最多 16 台，且**需要 cluster-aware 檔案系統**（一般 ext4/XFS 會毀損資料）

既有未加密的 EBS volume 要加密怎麼做？::**snapshot → 複製 snapshot 時加密 → 由該 snapshot 建新 volume**。無法就地加密

EBS snapshot 存在哪裡？::AWS 管理的 S3，**但不是你能用一般 S3 API 瀏覽的物件**

多台 Linux 跨 AZ 共享 POSIX 目錄 → 選什麼？::**EFS**

Windows + SMB + Active Directory → 選什麼？::**FSx for Windows File Server**

HPC / ML 訓練、高吞吐平行檔案系統、可連動 S3 → 選什麼？::**FSx for Lustre**

需要同時支援 NFS + SMB + iSCSI → 選什麼？::**FSx for NetApp ONTAP**

instance store 的資料什麼時候會消失？::**停止、休眠、終止**，或底層硬體故障時。只能當暫存

## 🪣 S3

S3 單次 PUT 的大小上限？超過怎麼辦？::**5 GB**，超過必須用 **multipart upload**（>100 MB 就建議用）

S3 物件的大小上限？::**5 TB**

S3 的耐久性是多少？::**99.999999999%（11 個 9）**

哪些 S3 類別的最低儲存期間是 30 天？::**Standard-IA 與 One Zone-IA**

Glacier 三兄弟的最低儲存期間？::Instant Retrieval **90 天**、Flexible Retrieval **90 天**、**Deep Archive 180 天**

存取模式完全不可預測、且不想有取回費風險 → 選什麼？::**Intelligent-Tiering**（唯一沒有取回費的分層方案）

為什麼「資料只保留 45 天」不能選 Glacier Flexible？::最低儲存期間 **90 天**，提前刪除仍要付滿——**反而更貴**

One Zone-IA 什麼時候是錯誤答案？::當資料**關鍵且無法重建**時（只存在單一 AZ）

「帳單上升但沒新增資料，有很多中斷的大檔上傳」怎麼解？::Lifecycle 規則 **`AbortIncompleteMultipartUpload`**——未完成的分段會持續計費且在物件清單看不到

Object Lock 的兩種模式差在哪？::**Governance mode** 特權使用者可繞過；**Compliance mode** **連 root 都不能刪改**

啟用 Object Lock 的兩個前提？::**建立 bucket 時啟用**（或透過支援請求）+ **必須同時啟用 versioning**

「bucket policy 允許公開但仍 403」先檢查什麼？::**S3 Block Public Access**——它的優先序高於任何 bucket policy 與 ACL

S3 Replication 的必要條件？預設會複寫既有物件嗎？::需要**啟用 versioning**；**預設只複寫啟用後的新物件**，既有物件要用 S3 Batch Replication

「全球使用者上傳到單一 bucket 很慢」用什麼？::**S3 Transfer Acceleration**（經 edge 再走 AWS 骨幹）。CloudFront 加速的是下載不是上傳

SSE-KMS 相對 SSE-S3 多了什麼？代價是什麼？::多了**金鑰使用的 CloudTrail 稽核**與**細粒度金鑰權限**；代價是需要額外 `kms:Decrypt` 權限與 KMS API 費用（可用 **S3 Bucket Keys** 降低）

## 🗄 RDS 與 Aurora

Multi-AZ DB instance 的 standby 可以讀嗎？::**不可以**。Multi-AZ DB **cluster** 才有可讀的 reader

Read Replica 會自動故障切換嗎？::**不會**，需要手動提升。它是**讀取擴展**不是 HA

「AZ 故障要自動切換」與「分攤讀取」分別選什麼？::自動切換 → **Multi-AZ**；分攤讀取 → **Read Replica**

RDS 自動備份的保留期範圍？::**0–35 天**（0 = 關閉）。支援 PITR

手動 snapshot 會隨 DB 刪除而消失嗎？::**不會**，保留到你手動刪除

「Lambda 併發量大，DB 回報 too many connections」→ 選什麼？::**RDS Proxy**（連線池）。加大 instance 是錯的，問題在連線數不在運算量

Aurora 的儲存有幾份副本？::**3 個 AZ 各 2 份，共 6 份**

Aurora 的三種 endpoint？::**Cluster endpoint**（寫入）、**Reader endpoint**（自動平衡到所有 reader）、**Custom endpoint**（指定子集）

Aurora Global Database 的 RPO 與 RTO？::**RPO ≈ 1 秒、RTO ≈ 1 分鐘**

Aurora replica 最多幾個？::**15 個**，故障切換時自動提升（可設優先 tier）

「間歇性、不可預測、大部分時間閒置」的關聯式資料庫 → 選什麼？::**Aurora Serverless v2**

## 🔑 DynamoDB 與快取

DynamoDB 的 item 大小上限？::**400 KB**（更大要放 S3 存指標）

GSI 支援強一致性讀取嗎？::**不支援，只有最終一致性**

LSI 與 GSI 最大的差別？::**LSI 只能在建表時建立**、同 partition key；**GSI 可隨時建立**、不同 partition key、有自己的容量

「整體容量還有剩卻一直被限流」代表什麼？::**熱分割區（hot partition）**——partition key 基數太低。加容量無效，要重新設計 key

DynamoDB 多 Region 都要能寫 → 選什麼？::**Global Tables**（active-active，最後寫入者勝）。**DynamoDB 沒有 read replica 這個概念**

DynamoDB PITR 可以還原到多久前？::**35 天**內任一秒

DAX 與 ElastiCache 怎麼選？::只加速 **DynamoDB** 且要求幾乎不改程式 → **DAX**；快取 RDS 查詢或需要通用資料結構 → **ElastiCache**

Redis/Valkey 相對 Memcached 多了什麼？::**持久化、複寫、Multi-AZ 自動故障切換、備份還原、豐富資料結構**

看到哪些關鍵字就一定選 Redis 而非 Memcached？::`high availability`、`persistence`、`failover`、`backup` 任一個

## 📊 分析與串流

SQS 與 Kinesis Data Streams 最根本的差別？::**SQS 的訊息被消費後刪除；Kinesis 的資料留在 shard，多消費者可各自讀取並重播**

Kinesis 單一 shard 的寫入與讀取上限？::寫 **1 MB/s 或 1,000 records/s**；讀 **2 MB/s**（共享型 consumer 合計）

Enhanced Fan-Out 提供什麼？::每個 consumer **各自獨享 2 MB/s**，且是 push 模式、延遲更低

Kinesis Data Streams 的保留期？::預設 **24 小時**，最長 **365 天**

Data Firehose 的最低緩衝時間？這代表什麼？::約 **60 秒**——所以它是「**近即時**」而不是即時

Firehose 的固定目的地有哪些？::**S3、Redshift、OpenSearch、Splunk、HTTP endpoint**

Athena 降低成本與提升效能的三招？::**列式格式（Parquet/ORC）+ 壓縮 + 分區**（因為按掃描資料量計費）

為什麼「為 Athena 換更大的 instance」一定是錯的？::**Athena 是無伺服器的，根本沒有 instance**

「即時全文檢索 + 互動式儀表板」→ 選什麼？::**OpenSearch Service**。偶爾查、要最省 → S3 + Athena

Redshift Spectrum 做什麼？::不載入資料，**直接從 Redshift 查詢 S3**（熱資料在倉儲、冷資料留 S3）

「既有應用使用 JMS，不能改程式碼」→ 選什麼？::**Amazon MQ**（這幾乎是它唯一的正解情境）

什麼時候才選 MSK？::**題幹點名 Kafka** 或既有 Kafka 要遷移。沒提到就不要選——維運負擔高
