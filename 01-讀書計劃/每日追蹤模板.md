### 錯因分類（統計後就知道該補什麼）

| 代號 | 意思 | 修法 |
|---|---|---|
| **判準** | 兩個服務都可行，選錯偏好 | 回讀 `04-模式與決策` 的決策樹 |
| **知識** | 根本不知道這個服務/功能 | 回讀對應的核心服務筆記 |
| **數字** | 記錯上限或預設值 | [[數字與門檻速查]] |
| **讀題** | 漏看關鍵限制詞 | [[常見陷阱與誘答選項識別]] Part 1 |
| **過度設計** | 選了可行但超出需求的方案 | 練習「先篩硬條件，再比價」 |
| **粗心** | 知道卻選錯、複選沒選滿 | 放慢、把選項全讀完 |

> [!tip] 這張表的價值
> 到 Day 20 時，你會發現錯因**高度集中在一兩類**。
> **針對錯因補，比針對主題補有效得多**——「讀題」錯 8 次的人，再讀十篇服務筆記也沒用。

## 🗓️ 每週回顧（15 分鐘，每個複習日做）

1. 這週哪個主題我能**不看筆記講給別人聽**？（那才是真的會了）
2. 哪個主題讀了兩次還是模糊？→ **改變方法**：畫圖 / 做 Lab / 查官方文件原文 / 去做該主題的情境題
3. 錯因最多的是哪一類？→ 下週針對**它**，不是針對主題
4. 時間有沒有跑掉？**若連續兩天沒完成，直接切換到 [[6 週穩紮計劃]]，不要硬撐**——落後的罪惡感比落後本身更傷進度

把所有 `importance: 5` 的筆記列出來，數一下各信心等級有幾篇：

| confidence | 篇數 | 意義 |
|:--:|:--:|---|
| 1–2 | | **考前必須清空這一格** |
| 3 | | 還需要一次複習 |
| 4–5 | | 穩了，只需閃卡維持 |

> [!warning] Day 21 的硬性檢查
> 若此時 `importance: 5` 的筆記還有超過 3 篇落在 confidence 1–2，**代表進度落後**。
> 處理方式：**延後考試日期**，或**明確放棄低頻主題**（[[遷移與混合雲]] 的 7R、ML 服務對照）把時間集中在 Domain 1。放棄也是策略。
